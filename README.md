# Split Translate
<img width="1903" height="834" alt="AppViewer" src="https://github.com/user-attachments/assets/c534af1d-a6db-4f9c-b483-4982b00619c8" />

Webページを左右に並べて表示する Chrome 拡張機能です。左（元のタブ）が原文、右（サイドパネル）がページをそのまま複製して文章だけを訳文に差し替えたもので、レイアウト・画像・リンクは元のページと同じまま読めます。

- マウスホバーで、原文⇔訳文の対応するブロックが連動してハイライトされます
- どちらをスクロールしても、もう片方が同じ位置まで追従します
- 翻訳は **ブラウザー内蔵翻訳（Chrome / Edge、無料・ローカル）** / **Ollama（ローカル）** / **OpenAI互換API** / **Anthropic（Claude）** / **Google Cloud Translation** / **Azure AI Translator** から選べます。複数の接続設定を保存しておき、ツールバーから切り替えられます
- Chrome内蔵のLocal LLM（Prompt API / Gemini Nano）、Ollama、OpenAI互換API、Anthropicに、現在読んでいる原文・訳文について質問できます。チャットはドメイン・接続設定ごとに分離されます
- Local LLMチャットの回答はMarkdown（見出し・リスト・引用・コード・リンク・表など）で表示されます。回答内のHTMLは実行されません

## できないこと / 制限事項

- `<pre><code>` のようなコードブロックは翻訳しません（構造を壊さないため、意図的に対象外にしています）
- 1ページあたりの抽出上限は既定で5,000ブロックです。設定ヘッダーから100～10,000ブロックの範囲で変更でき、次回のページ抽出から反映されます。安全のため25万文字の固定上限もあります
- SPA（`history.pushState` 等でページ遷移するサイト）では、別ページへ移動しても自動では再抽出しません。内容が古い・足りないと感じたら、拡張機能アイコンをもう一度クリックして再抽出してください
- 翻訳パネルはスクリプトを無効化した複製なので、元ページ側の動的な機能（フォーム送信やJS駆動のUIなど）は動作しません。閲覧・翻訳専用です

## インストール（開発者モードで読み込み）

1. このリポジトリをクローンまたはダウンロードする
2. Chrome で `chrome://extensions` を開く
3. 右上の「デベロッパーモード」をオンにする
4. 「パッケージ化されていない拡張機能を読み込む」でこのフォルダを選択する
5. ツールバーに拡張機能のアイコンが表示される

## 使い方

1. 翻訳したいページを開き、拡張機能アイコンをクリック（または `Alt+Shift+T`）
2. サイドパネルが開き、本文の抽出・翻訳が始まる
3. 必要な場合は右上の「設定」でヘッダーを開き、翻訳元（自動検出または手動）・翻訳先の言語とモデル設定を選べる
4. 原文側・パネル側のどちらでスクロール/ホバーしても、もう片方が連動する
5. 処理が重いと感じたら「一時停止」ボタンで翻訳を止められる（再開ボタンで続きから再開）
6. 翻訳に失敗した文（赤い破線の枠）はクリックすると再翻訳される
7. 右下の「AI」でパネル下部にLocal LLMチャットを開き、現在表示中の箇所や選択中の文章について質問できる

「設定」と「AI」のフローティングボタンはドラッグで移動でき、位置は保存されます。チャット枠上端のハンドルを上下にドラッグすると高さを変更でき、その高さも保存されます（ダブルクリックで初期値に戻ります）。ハンドルを最下部まで下げるとチャットを閉じ、画面下端に残るハンドルを上へドラッグすると再び開けます。「AI」ボタンから開いた場合は既定の高さへ戻ります。

キーボードでは `Escape` を押すたびに、情報パネル、モデル設定、設定ヘッダー、チャットの順で開いているUIを一段ずつ閉じます。チャットは `Ctrl+Enter`（macOSでは `⌘+Enter`）で送信できます。チャットの高さ調整バーは上下矢印で変更でき、`Home`で最小、`End`で最大になります。

## Local LLM チャット

チャット上部で、Chrome内蔵の Prompt API（Gemini Nano）またはチャット用に保存したOllama・OpenAI互換API・Anthropic設定を選べます。翻訳用のモデル設定とは別に保存・管理されるため、それぞれ異なるモデルや接続先を利用できます。Google Cloud TranslationとAzure AI Translatorは翻訳専用APIのため、チャットには利用できません。ホバー中または表示中のブロック周辺とその訳文、パネル内で選択した文章をコンテキストとして渡します。Web検索機能はありません。

チャット上部の「ⓘ」では、Local LLMのストレージ・メモリ・GPU/CPU要件、ページ文脈の選択規則、外部APIへ送信される情報を確認できます。`chrome://on-device-internals/`（モデル状態・ログ）と `chrome://components/`（モデルコンポーネント更新）を開くトラブルシューティング用ボタンもあります。Chromeが内部ページを直接開けない場合は、そのアドレスをクリップボードへコピーします。

利用モデルを変更するには、チャット上部の「モデル設定」を押し、「LLMチャットモデル設定を編集」でプロバイダー・URL・モデル名などを変更します。最初に作られるChrome内蔵LLM設定も、Ollama・OpenAI互換API・Anthropicへ自由に変更できます。複数の設定がある場合は、チャット上部の選択欄で使用する設定を切り替えます。Chrome内蔵Local LLMを選んでいる間はモデルをChromeが管理するため、モデル名は変更できません。翻訳側とチャット側の設定は最初から独立しており、相互に複製・同期されません。

会話履歴とモデルセッションはドメイン・接続設定ごとに分離します。履歴は `chrome.storage.session` に保存され、ブラウザーを終了すると消去されます。Chrome内蔵LLMはモデルの初回取得後、文章や会話を外部へ送信せず端末内で処理します。初回のモデル取得や実行には、Chromeが定めるメモリ・CPU/GPU・空き容量の要件を満たす必要があります。Ollama・OpenAI互換API・Anthropicを選んだ場合は、ページ文脈と会話が設定した接続先へ送信されます。

ページ文脈は質問とのキーワード一致、現在表示中の位置、パネル内の選択範囲から必要なブロックを優先して組み立てます。挨拶などページを参照しない質問では文脈を付けません。「LLMチャットモデル設定」で設定ごとの最大文字数を変更でき、`0` にするとページ文脈を一切付けません。既定値は4,000文字です。この値はJavaScriptの文字数であり、モデル内部のトークン数ではありません。Chrome Prompt API自体はセッションごとの `contextUsage` / `contextWindow` で文脈量を管理します。

Chrome内蔵LLMの初回取得時は「ダウンロード開始中」「ダウンロード中（進捗率）」「モデル読込中」「回答中」を区別して表示します。モデル取得には数分かかる場合があり、その時間は回答のタイムアウトに含めません。

Chrome内蔵LLMの回答は生成された部分からストリーミング表示します。回答中は「停止」で生成を中断できます。セッション作成後、90秒間新しい出力がない生成は自動停止し、Chrome内蔵LLMの該当セッションを破棄します。ドメインや設定を切り替えた場合も、使用していない内蔵モデルセッションを破棄してメモリを解放します。

## 翻訳モデル設定

ツールバーの「モデル設定」から、保存済みの翻訳設定を切り替えられます。「翻訳モデル設定を編集」を開くと、名前・プロバイダー・接続先URL・APIキー・モデル名を編集できます。「新規追加」で別の設定を追加し、用途に応じて使い分けられます（例: 普段はローカルのOllama、精度重視のときだけクラウドのモデル）。チャット用設定はこの一覧とは独立しています。

### ブラウザー内蔵翻訳（Chrome / Edge、ローカル、無料）

デスクトップ版 Chrome 138 以降または対応版Edgeの Translator API を使います。初回の翻訳時にブラウザーが必要な言語モデルをダウンロードし、以降の翻訳は端末内で実行します。APIキーやOllamaのインストールは不要です。翻訳元は本文から自動検出しますが、誤検出するページではツールバーから手動指定できます。実際に使用中の言語ペア（例: `en → ja`）も進捗欄に表示します。

### Ollama（ローカル、無料、オフラインで使える）

既定のモデルは [`mitmul/plamo-2-translate`](https://ollama.com/mitmul/plamo-2-translate) で、日英翻訳に特化した専用のプロンプト処理（文単位の分割、暴走検出、再試行）を行います。モデル名に `plamo` を含まない Ollama モデルを指定した場合は、Ollama 標準のチャットテンプレートに素直な翻訳指示を渡す汎用処理に切り替わります（他言語や、好みのモデルを使いたい場合向け）。

セットアップ:

```sh
# Ollama をインストール後
ollama pull mitmul/plamo-2-translate
# ブラウザ拡張機能からのアクセスを許可する
OLLAMA_ORIGINS="chrome-extension://*" ollama serve
```

Mac で `launchctl` 経由で起動している場合は、環境変数の設定方法が異なります。`launchctl setenv OLLAMA_ORIGINS "chrome-extension://*"` を実行してから Ollama を再起動してください。

### OpenAI互換API

OpenAI本体のほか、Groq・OpenRouter・DeepSeek・LM Studio・text-generation-webui など、`/chat/completions` エンドポイントを持つサービス全般に対応します。URL には `/v1` までを含めて入力してください（例: `https://api.openai.com/v1`）。APIキーが必要です。

### Anthropic

Claude の Messages API を使います。URL の既定値は `https://api.anthropic.com`。APIキーが必要です。

### Google Cloud Translation

翻訳専用の公式API（Basic v2）です。チャット用のモデル名や指示文（テンプレート）の概念はありません。[Google Cloud Console](https://console.cloud.google.com/apis/credentials) でAPIキーを発行してください。**月50万文字まで無料**（期限なし）、以降は100万文字あたり$20です。

### Azure AI Translator

Microsoft の翻訳専用API（v3.0）です。こちらもモデル名や指示文はありません。[Azure Portal](https://portal.azure.com/) で Translator リソースを作成し、サブスクリプションキーを取得してください。多くのリソースでは**リージョン**の指定も必要です（リソース作成時に選んだリージョン、例: `japaneast`。グローバルリソースの場合は `global`）。**月200万文字まで無料**（期限なし）、以降は100万文字あたり$10です。

### 自前サーバーや他のクラウドAPIを使う場合（ホスト権限）

`localhost` / `127.0.0.1`（Ollama）、`api.openai.com`、`api.anthropic.com`、`translation.googleapis.com`、`api.cognitive.microsofttranslator.com` 以外のURLを設定すると、Chromeがそのサイトへのアクセス許可を一度確認します。モデル設定のURL欄を保存すると許可ダイアログが出るので、許可してください。許可されなかった場合は通知欄にその旨が表示されます。

## プライバシー

**本拡張機能は、ユーザーデータを開発者のサーバーへ送信しません。開発者によるデータ収集・保管の仕組みはありません。** 設定や一時データはユーザーの端末内に保存し、外部APIを選んだ場合は、端末から選択した接続先へ直接通信します。

**初回利用時の既定設定では、翻訳・AIチャットともにChrome内蔵のローカルモデルを使用し、外部サービス上のモデルは使用しません。** 設定を変更した場合は、次回以降も保存済み設定を使用します。翻訳・チャット処理のためのデータは、ユーザーが選択・設定した接続先以外へ送信しません。ブラウザーによるモデル取得・更新や、ページ表示用の画像・CSS等の取得に伴う通信は発生する場合があります。

詳しくは [プライバシーポリシー](PRIVACY.md) をご確認ください。

- Chrome内蔵翻訳では翻訳を端末内で処理します。Ollamaは設定した接続先で処理し、同じ端末のOllamaを指定すれば端末内で処理できます。OpenAI/Anthropic等の外部APIを選んだ場合は翻訳テキストがそのAPIに送信されるため、機密情報を含むページではご注意ください
- チャットでChrome内蔵LLMを選んだ場合は端末内処理です。Ollama・OpenAI互換API・Anthropicを選んだ場合は、質問・会話履歴・関連するページ文章が設定した接続先へ送信されます。Web検索は行いません
- APIキーは `chrome.storage.local`（この拡張機能専用のローカルストレージ）に保存され、設定した翻訳・チャット接続先への認証に使用されます
- ページのURL・タイトル・本文などを表示と処理のために一時保存します。ホバー・スクロール・選択状態は同期やチャットの文脈選択に使用します
- 元ページの表示を再現する際、画像・CSS等をその配信元から読み込む場合があります
- 翻訳結果はタブごとのキャッシュとして `chrome.storage.session`（ブラウザを閉じると消える）に保存されます

## 開発者向け: 構成

| ファイル | 役割 |
| --- | --- |
| `background.js` | アイコンクリックで本文を抽出・保存。ページ遷移時に古い抽出結果を破棄 |
| `content.js` | 元ページに常駐。本文ブロックの抽出、複製HTMLの生成、ホバー/スクロール同期 |
| `compose.js` | 訳文を元のDOM構造（リンク・強調など）に復元する |
| `scrollsync.js` | 本文のスクロール領域を自動検出するロジック（`content.js`・`viewer.js` で共用） |
| `translate.js` | 翻訳バックエンド（Chrome内蔵翻訳 / Ollama / OpenAI互換 / Anthropic / Google Cloud Translation / Azure AI Translator）の呼び出し |
| `viewer.js` / `viewer.html` / `viewer.css` | サイドパネル本体 |

content.js と viewer.js 側の両方で、スクロール連動・モデル設定・プロファイル切り替えのロジックが動いています。詳しい設計意図は各ファイル冒頭のコメントを参照してください。

## 配布用 ZIP の作成と公開

Python 3.9 以降で、リポジトリのルートから実行します。

```sh
python3 scripts/package.py
```

`manifest.json` のバージョンを使って、`dist/split-translate-<version>.zip` と
`dist/split-translate-<version>.zip.sha256` を生成します。
ZIP には実行に必要なファイルと LICENSE だけを含め、`manifest.json` を ZIP の直下に配置します。
`.git`、開発用スクリプト、README、OS の隠しファイルは含みません。
実行用ファイルを追加したときは `scripts/package.py` の `FILES` も更新してください。

### GitHub Actions による公開（推奨）

`.github/workflows/release.yml` は `v*` タグを push したときだけ実行されます。
通常のブランチへの push や PR ではリリースを作成しません。
タグ名と `manifest.json` のバージョンが一致することを確認し、ZIP と SHA-256 を生成・検証して GitHub Release に添付します。
認証には GitHub Actions の `GITHUB_TOKEN` を使用するため、個人トークンの登録は不要です。
同じタグのリリースがすでに存在する場合は失敗し、公開済みの添付ファイルを上書きしません。

公開手順:

1. `manifest.json` のバージョンを更新し、動作確認したソース・配布スクリプト・ワークフローをコミットして GitHub に push します。
2. 公開するコミットにタグを付けて push します（以下は `3.10.0` の例です）。

   ```sh
   git tag v3.10.0
   git push origin v3.10.0
   ```

3. GitHub の Actions で `Release extension` の成功を確認し、Releases から作成されたリリースを開きます。
4. リリースに添付した ZIP と `.sha256` を同じフォルダへダウンロードし、そのフォルダで次を実行して `OK` を確認します（ファイル名は実際のバージョンに置き換えます）。

   ```sh
   shasum -a 256 -c split-translate-3.10.0.zip.sha256
   ```

5. ダウンロードした **その ZIP を再圧縮せずに** Chrome ウェブストアの開発者ダッシュボードへアップロードします。

GitHub が自動生成する `Source code (zip)` ではなく、自分で添付した ZIP を使います。
これで GitHub で配布する ZIP とストアに提出する ZIP をバイト単位で同一にできます。
ストアからインストールされるパッケージには Google による署名などが加わるため、提出 ZIP 自体とは区別してください。
ストアの公開には、別途ストア掲載情報・プライバシー情報の入力と審査が必要です。
この CI は GitHub Release の公開までを行い、Chrome ウェブストアへのアップロードは手動です。
アップロードに失敗して下書きリリースが残った場合は、添付ファイルの状態を確認してください。
再実行するには未公開の下書きを削除してから Actions の失敗した実行を再実行します。公開済みリリースの修正には新しいバージョンとタグを使います。
